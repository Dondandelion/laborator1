8. Контрольные вопросы:

    1. Что такое виртуализация и зачем она используется?
    
        Виртуализация — это технология, позволяющая запускать на одном физическом компьютере несколько изолированных виртуальных сред (виртуальных машин), каждая из которых работает как отдельный компьютер со своей операционной системой,       процессором, памятью и диском. Ресурсы физического оборудования делятся между ними с помощью программного слоя, который называется гипервизором.

        Используется для того, чтобы:

        1. эффективнее использовать оборудование (вместо нескольких недогруженных серверов — один мощный);
        2. изолировать приложения и ОС друг от друга (сбой или взлом одной ВМ не затрагивает остальные);
        3. безопасно тестировать ПО и экспериментировать, не рискуя основной системой;
        4. быстро создавать, копировать, переносить и восстанавливать окружения (снимки состояния, клонирование);
        5. запускать разные операционные системы на одном компьютере;
        6. экономить на оборудовании, электроэнергии и администрировании.

    2. Какие функции выполняет QEMU?

        QEMU (Quick Emulator) — это эмулятор и средство виртуализации с открытым исходным кодом. Его основные функции:

        1. эмуляция аппаратного обеспечения: процессора, оперативной памяти, жёстких дисков, сетевых карт, видеоадаптера, USB-контроллеров и т. д.;
        2. запуск гостевых операционных систем (например, Debian) внутри виртуальной машины на хосте;
        3. эмуляция разных архитектур процессоров (x86, ARM, MIPS, RISC-V и др.);
        4. работа в связке с KVM (модуль ядра Linux) в режиме аппаратной виртуализации, что даёт производительность, близкую к нативной;
        5. создание и управление образами дисков (утилита qemu-img, формат qcow2 с поддержкой снимков и динамического выделения места);
        6. настройка сети (в т. ч. проброс портов), загрузка с ISO-образов, работа с USB и другими устройствами.

    3. Что представляет собой стек LAMP?


        LAMP — это набор программного обеспечения с открытым исходным кодом для создания и запуска динамических веб-сайтов и веб-приложений. Название — аббревиатура компонентов:

        1. Linux — операционная система;
        2. Apache — веб-сервер, принимающий HTTP-запросы и отдающий страницы;
        3. MySQL (или MariaDB) — система управления базами данных для хранения данных;
        4. PHP (также Perl или Python) — язык программирования, на котором выполняется серверная логика и генерируются динамические страницы.

        Браузер отправляет запрос Apache, тот передаёт обработку PHP-скрипту, скрипт при необходимости обращается к базе данных, формирует HTML-страницу, и Apache возвращает её клиенту.

    4. Как проверить работу Apache и PHP?

        Apache:

        1. командой curl http://localhost внутри ВМ — в ответ должна прийти HTML-страница по умолчанию («Apache2 Debian Default Page»);
        2. в браузере на хосте по адресу http://localhost:8080 (если настроен проброс порта) или http://<ip_виртуальной_машины>;
        3. проверкой состояния службы: sudo systemctl status apache2.

        PHP:

        1. создать тестовый файл:
        2. echo "<?php phpinfo(); ?>" | sudo tee /var/www/html/info.php
        3. открыть в браузере http://<ip_виртуальной_машины>/info.php — должна отобразиться страница с информацией о версии PHP и его конфигурации. Если вместо этого скачивается файл или виден исходный код, значит модуль PHP для Apache не работает;
        4. можно также выполнить php -v в терминале, чтобы увидеть установленную версию.

    5. Для чего используется phpMyAdmin?

        phpMyAdmin — это веб-приложение на PHP для администрирования баз данных MySQL/MariaDB через браузер, без необходимости писать команды в консоли. С его помощью можно:

        1. создавать, изменять и удалять базы данных, таблицы, поля и индексы;
        2. просматривать, добавлять, редактировать и удалять записи;
        3. выполнять SQL-запросы;
        4. управлять пользователями и их правами доступа;
        5. импортировать и экспортировать данные (SQL, CSV и др.), делать резервные копии;
        6. отслеживать состояние сервера и настройки.

    6. Какой смысл имеет файл .gitignore в проекте?

        Файл .gitignore содержит список шаблонов файлов и папок, которые Git должен игнорировать: они не отслеживаются, не попадают в коммиты и не отправляются в удалённый репозиторий.

        В данной работе он исключает файлы *.iso, *.img, *.qcow2 (образы дисков и ОС, весящие гигабайты), а также логи и временные файлы. Это нужно, чтобы:

        1. не раздувать репозиторий большими бинарными файлами (у GitHub есть ограничение на размер файла в 100 МБ);
        2. не хранить в истории мусор, временные и автоматически генерируемые файлы;
        3. не публиковать конфиденциальные данные (пароли, ключи, файлы конфигурации с секретами);
        4. держать в репозитории только исходные материалы, нужные для работы проекта.
